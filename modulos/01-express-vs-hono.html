MÓDULO 01 · HONO

Hono: rotas, contexto e middleware

Entenda como Hono organiza rotas, handlers e middleware em uma API.

Uma aplicação Hono

Uma aplicação é uma composição de rotas. Cada handler recebe um contexto c, que reúne a requisição e os recursos para montar a resposta.

import { Hono } from 'hono';

const app = new Hono();
app.get('/artigos/:id', (c) => {
  const id = c.req.param('id');
  return c.json({ id, titulo: 'Clínica e cultura' });
});

O contexto c evita manipular objetos separados como req e res. Em rotas OpenAPI, registraremos handlers com router.openapi(route, handler).

Middleware e composição

Middleware envolve o fluxo da requisição e pode executar lógica antes e depois de next().

app.use('/artigos/*', async (c, next) => {
  const inicio = Date.now();
  await next();
  console.log(c.req.path, Date.now() - inicio);
});

O router do recurso é montado em um prefixo no app.ts. Assim, cada domínio permanece agrupado sem concentrar todos os handlers na aplicação principal.

Hono oferece o fluxo HTTP. A separação de responsabilidades continua definida pela arquitetura do módulo.
