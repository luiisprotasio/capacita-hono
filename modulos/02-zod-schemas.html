MÓDULO 02 · ZOD

Zod: validar entradas e derivar tipos

Separe validação em tempo de execução de tipagem estática e use schemas para estabelecer contratos consistentes.

Tipo TypeScript não valida JSON

Uma interface TypeScript desaparece depois da compilação. Um cliente ainda pode enviar um valor inesperado; um schema em runtime pode rejeitá-lo.

const StatusSchema = z.enum(['rascunho', 'publicado']);
const UpdateStatusSchema = z.object({ status: StatusSchema });
type UpdateStatusInput = z.infer<typeof UpdateStatusSchema>;

O schema valida o valor e também permite derivar o tipo UpdateStatusInput. Com @hono/zod-openapi, os metadados podem compor o contrato OpenAPI.

Entrada, saída e regra de negócio

  • Schema de entrada: define body, parâmetros e query aceitos.
  • Schema de resposta: descreve os campos devolvidos pela API.
  • Regra de negócio: permanece no service; Zod não decide se o artigo pode ser publicado.
const CreateArtigoSchema = z.object({
  titulo: z.string().trim().min(3),
  resumo: z.string().optional(),
}).openapi('CreateArtigoInput');

Validar que status é publicado não verifica se o artigo existe nem se a publicação é permitida. Isso depende da regra no service.
